# Daily Progress Report - 2026-01-13

## Features Implemented
1.  **Channel Administration**:
    -   **`KICK` Command**: Implemented functionality for channel operators to remove users from a channel. Includes checks for operator privileges, user presence, and broadcasts the kick message with an optional reason.
    -   **`INVITE` Command**: Implemented functionality for channel operators to invite users to a channel. Includes checks for existence/presence and sends `RPL_INVITING` confirmation. Now also whitelists the user for `+i` channels.

2.  **Channel Modes (`MODE` Command)**:
    -   **`i` (invite-only)**: Restricts access to invited users only.
    -   **`t` (topic restriction)**: Only operators can change the channel topic.
    -   **`k` (key/password)**: Channels can be protected with a password.
    -   **`o` (operator)**: Operators can grant/revoke operator status to others.
    -   **`l` (limit)**: Channels can have a maximum user limit.

3.  **Channel Topics (`TOPIC` Command)**:
    -   Users can view the current channel topic.
    -   Operators (or anyone if `-t`) can set a new topic.
    -   Topic changes are broadcasted to all channel members.

4.  **Critical Bug Fixes**:
    -   **Memory Corruption / Crash**: Fixed a critical use-after-free bug in `Server::ReceiveNewData` where the server would attempt to access a client's buffer after the client had disconnected (and had been deleted) via the `QUIT` command.

## Documentation
-   Created `progressMD/testing_guide.md` with detailed instructions on how to test all features using `netcat` and `irssi`.

## Future Roadmap / Missing Functionality
To complete the `ft_irc` project requirements, the following features still need to be implemented:

1.  **Robustness & Cleanup**:
    -   **Error Handling**: Ensure all commands return appropriate numeric replies (e.g., `4xx` and `5xx` errors) for edge cases.
    -   **Input Parsing**: Strengthen parsing to handle fragmented packets (though `\r\n` handling is partially in place) or flooding.
